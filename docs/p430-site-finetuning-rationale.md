# P430 타일 학습의 연구 근거와 적용 범위

2026-11-24 · [설치 환경 맞춤 학습 계획](p430-site-finetuning-plan.md)

P430 2차 개발 영상에서 칼 박스 짧은 변의 중앙값은 전체 영상을 960에 넣었을 때 8.3px였다. 중앙 1920×1080에서 768×640 타일을 잘라 640에 넣으면 같은 위치의 칼은 이론상 약 13.8px로 들어간다. 이는 letterbox 축척으로 계산한 값이다. 배경이나 가림에 사라진 영상 정보는 복원되지 않는다. 기존 가중치의 저오탐 결과가 전체 0/316에서 타일 5/316으로 변했고, 타일에서 낮은 점수 후보까지 남기면 199개가 정답과 겹쳤다. 그 결과가 타일 학습을 먼저 시도할 근거이며, 검출·경보 개선은 새 실험 대상이다. 타일 실험의 가설은 같은 부모와 업데이트 수에서 입력 축척이 작은 칼의 정검출을 높인다는 것이다. 백본 실험의 가설은 부분 학습이 기존 특징의 손실을 줄인다는 것이다. 둘 다 열어 두기 위해 전체/타일 × 전체 학습/백본 동결 네 조합을 같은 데이터로 실행한다. 각 가중치는 전체 화면과 타일 추론에서 각각 평가한다. 검출 점수와 임계값은 tune에서 비교하고 고정된 검출점을 dev-check에 전송한다. AP, 작은 칼·전체 recall과 음성 FP를 기록하며, 별도 시간 정답이 확보된 개발 영상에서 사건 지표를 검증한다.

보호된 최종 편집본은 사용자가 별도 11/24 촬영분이라고 확인했다. 편집본의 파일 해시만 보호 목록에 넣었고 영상과 정답은 학습 PC에 복사하지 않는다. 원본 녹화 SHA 및 편집 컷의 원본 매핑은 독립 최종 평가 전에 보강할 수 있는 검증 근거다.

PC14 1차 시작은 타일 좌표 직렬화 비교 오류에서 멈췄다. 생성된 이미지와 라벨 SHA는 일치했고 좌표 형식을 수정한 뒤 재실행했다. 실패 로그를 보존했다. 학습 실행기는 PC11–13 `6c5a2a3`, PC14 `596ebbe`이다. - 실행과 원시 예측의 위치는 각 PC의 `C:\Class6\edge-threat-response\runs\p430-site-20261124-v1`이다. 장비별 실행 폴더에서 `state.json`과 이후 `result.json`을 조회한다. 초기 가중치 SHA는 기존 혼합 `c6e5244f649de9722c956e0c861e98975c4334e08cdd9c0a6a74dd53f0e28d0a`, 공통 계획 SHA는 `8a92eefb8f4bf275d5ace1aae46edb37ad7c6fce02a0484e497fec96deb0a28c`다. 실행 완료 후 각 checkpoint의 tune 평가와 두 추론 경로의 선택 가중치 dev-check가 자동 실행된다.

## 11/24 비교 평가 복구

PC11~14의 학습 CSV에 12개 epoch가 모두 기록됐고 `best.pt`, `last.pt`, 0/3/6/9 epoch 체크포인트가 보존됐다. Ultralytics는 훈련이 끝난 뒤 검증 전용 `final_eval`에서 `on_fit_epoch_end`를 다시 호출한다. 이때 학습 배치를 검사한 것이 실패 원인이었다. 검사 hook을 실제 학습 epoch 종료로 옮겼다.

`e61bed7` 평가 실행기는 12개 학습 epoch와 이전 실패 사유·입력 계획·설정·초기 가중치 SHA를 확인하고 저장 가중치로만 비교 평가를 재개한다. 각 장비의 `evaluation-recovery.json`에 최초 상태, 호출 기록 SHA, 학습 CSV SHA, 평가 입력 가중치 SHA를 보존했다. 재개 PID는 PC11 3852, PC12 23708, PC13 9700, PC14 16136이며 네 곳에서 평가 단계와 최초 예측 파일을 확인했다. 큐·박스 평가 테스트 13개가 통과했다. 최종 홀드아웃과 사건 평가는 이 복구와 별개다.
