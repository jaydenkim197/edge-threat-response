## PC13 준비와 검수 순서

1. 입력과 결과는 `D:\edge-threat-response-data\video-intake\frame-screening` 아래에 있다. `pc13-20261111-v1/frames.jsonl`은 1초 샘플링과 중복 제외 후 S1 모델로 판정한 입력이다. `config.json`에는 RTX 3060, 모델 SHA-256, 입력 해상도 640, confidence 0.10을 기록했다.
2. `review-queue-20261111-v1/queue.jsonl`은 각 프레임의 SHA-256, 원본 영상, 시간, 배치와 배치 내 순번을 저장한다. 첫 100장은 두 유형을 50장씩 배치했다. 이후에는 영상별로 고르게 순환하며 전체 후보 비율로 섞어 최대 250장씩 나눈다.
3. `review-queue-20261111-v1/staging/video-0001`의 100장과 제안 박스 59개를 파일 해시와 좌표 범위로 확인했다. 다음 배치는 `python tools/prepare_video_frame_review.py pack <프레임 폴더> <대기열 폴더> <배치 번호> <팩 저장 폴더>`로 한 묶음씩 준비한다.
4. 출처의 팀 검수 사용 조건과 비공개 접근을 확인한 팩만 등록한다. 영상 팩은 기존 팀 검수 앱에서 `review_schema: "video-box-v1"`과 명시적 `reviewer_login: "code"`를 사용한다. 합성 테스트에는 격리된 설정과 DB를 사용한다. 접근·이용 조건은 [제한 자료 처리 원칙](../research-overview-en.md)을 따른다.
5. 검수자는 CCTV형 여부와 칼 유무를 고른다. 칼이 보이면 제안 박스를 옮기거나 조절하고, 필요할 때 박스를 추가하거나 삭제한 뒤 저장한다. 미검출 후보에서 칼이 보이면 박스를 새로 그린다. 애매한 장면은 `모르겠음`으로 저장한다.
6. 첫 팩의 완료·보류 건수와 검수 속도를 확인한 후 다음 팩을 연다. 기존 사이트는 시작 시 등록 이미지를 확인하고 요청 때 등록 항목을 읽는다. 후속 확대 전에 누적 등록 규모에서 시작·조회 시간을 다시 측정한다.

## 상태

- 대기열과 PC13 첫 팩 준비 `VERIFIED`. 105,828장의 경로와 해시가 원본 프레임 목록과 일치한다.
- 영상 편집 모드와 판정 이력 `VERIFIED`(합성 자료, 격리 DB). 자동 테스트 211개 중 209개 통과, 2개 건너뜀. 390px Chromium 모바일 화면에서 기존 박스 이동·크기 수정, 터치로 신규 박스 추가, 칼 없음 판정, 재로그인 후 저장 복원과 가로 넘침 0을 확인했다.
- 실제 영상의 팀 등록 `BLOCKED`. 출처별 팀 검수 허용 범위와 비공개 접속 준비가 남아 있다. 현 운영 사이트는 이름 선택 방식이다.
- 영상 검수는 후보별 사람 판정이다. 학습 승인과 보호된 평가 그룹 검사는 기존 데이터 정책을 적용한다.
