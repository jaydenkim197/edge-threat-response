# P430 2차 최적화 실험 계획

2026-11-26 · `PROPOSAL` · Track A 학습 자원 RTX 3060 PC11~14와 연구실 서버 RTX 3080 두 장 · Jetson Orin Nano에서 실기기 평가

## 기준점과 가장 큰 오류

D0는 기존 S1+CCTV 가중치다. D1은 PC13의 첫 epoch 저장본 `epoch0.pt`(SHA-256 `212a4b80e44674a3863daf240e127af797ac34f235a6e8356f23936b6348d190`), 중앙 1920×1080의 768×640 겹침 타일 6개, 모델 입력 640, 튜닝 confidence 약 0.2878이다. 원래 계획은 12 epoch이고 이 저장본은 첫 1,024 미니배치 이후다. 실제 시작 profile은 seed 3407, AdamW, LR 설정값 0.0001, warm-up 1 epoch, batch/nbs 8이다. 이력과 가중치 해시를 유지한다. 경보 설정 동결 또는 독립 테스트 완료는 별도의 작업이다. [1차 검증 기록](p430-site-finetuning-rationale.md)

개발 확인 287장의 D1 결과는 작은 칼 47/58, 나머지 34/82, 전체 81/140, 음성 프레임 오탐 0/147, 전체 FP 박스 23개다. AP50 61.82%와 AP50–95 18.04%의 간격으로 위치 정확도와 박스 경계 문제를 점검할 이유가 생긴다. 놓친 59개 중 48개(81.4%)가 작은 칼 구간 밖이다. 동일 D1 가중치에서 전체 화면과 타일을 따로 돌려, 누락이 타일 경계·낮은 confidence·병합·객체 부분 가림·처음부터 후보가 없었던 경우인지 집계한다. 기존 PC13의 전체 화면 행은 다른 가중치 `last.pt` 결과라서 같은 가중치 실험을 먼저 한다. 0/147은 관측된 개발 표본의 값이며 연속 프레임의 상관관계와 별도의 실제 경보 평가가 남는다.

## 1차 실행 제안

| GPU | 첫 작업 | 비교 목적 |
| --- | --- | --- |
| PC11 RTX 3060 | D1 조합 seed 3408 반복 | 같은 예산에서 초기 개선 재현 |
| PC12 RTX 3060 | D1 조합 seed 3409 반복 | 특정 seed의 우연한 개선 여부 |
| PC13 RTX 3060 | D1 고정 추론 및 원좌표 결합 | 전체·타일로 검출 가능한 객체가 보완되는지 검사 |
| PC14 RTX 3060 | 양성 불일치·음성 오탐 원인 분류, train 검수 팩 준비 | 다음 학습이 배경 오탐 또는 라벨 손실을 실제로 보완하는지 판별 |
| 연구실 RTX 3080 물리 ID 0 · 10 GiB | COCO 초기 YOLO26n, D1과 동일 자료·학습 조건으로 시작 | n/s 규모 비교용 초기 이력 대조군 |
| 연구실 RTX 3080 물리 ID 5 · 10 GiB | COCO 초기 YOLO26s | 모델 용량 증가 효과와 직접 배포 가능성 평가 |
| 후속 슬롯 | n/s 이후 표준 n의 대조 조건과 YOLO26n-P2 짧은 학습·내보내기 검증 | P2의 특징맵 효과와 배포 비용 확인 |
| Jetson Orin Nano | D1 및 통과 후보, 6타일·전체 화면+고정 ROI 비교 | 검출 이득이 실제 런타임 비용에서 유지되는지 검증 |

- 연구실 서버에서 3080 두 장이 유휴였음을 확인했다. 사용자 가상환경과 Linux 데이터 릴리스, GPU별 단독·동시 smoke를 통과한 뒤 각각 독립 run을 실행한다. RTX 3090 1·2는 다른 연구에 사용 중이므로 m 학습과 증류를 초기 큐에서 보류한다. GTX 1080 Ti 3·4는 권한 확인 대기다. 연구실 Track B는 Track A가 반환한 슬롯을 같은 UUID 잠금으로 사용한다. [환경·전송·동시 작업 계획](lab-gpu-training-plan.md)
- 재현은 D1과 같은 시작 가중치, 출처 P430/외부 CCTV/M2 50/30/20, 동일 샘플링 규칙과 warm-up을 적용한다. 첫 epoch의 256/512/768/1,024 미니배치와 이후 epoch마다 EMA 기준 가중치, 실제 optimizer step 및 LR을 기록한다. 초기 이득이 반복된 뒤에 LR을 0.00005와 기존 0.0001로 한 번 비교한다. 기존 스케줄이 바뀌지 않게 비교한다.
- 크기 비교는 n/s를 각각 같은 COCO 사전학습 단계에서 출발시키고, 같은 학습 데이터와 실제 optimizer update 예산을 맞춘다. batch 차이가 불가피하면 유효 batch·정밀도·BN 조건을 보고한다. 역사적 S1+CCTV 초기값을 쓴 D1과는 운용 후보 비교를 병기한다. YOLO26m은 충분한 VRAM과 사용 승인 확보 후에 같은 조건으로 추가한다. YOLO26l/x는 m의 유효한 개선 이후 확장한다. [YOLO26 공식 모델](https://docs.ultralytics.com/models/yolo26/)
- P2는 stride 4 특징맵을 더한다. 입력의 칼 픽셀이 보존된 상태에서 로컬 특징의 공간 해상도가 성능을 제한하는지 확인하는 실험이다. 표준 n과 같은 입력·자료·초기화 출처를 사용하고, 공통 backbone에 이식한 범위와 새로 초기화한 neck/head를 기록한다. 공식 YAML은 PC13 설치본에 있다. 짧은 CUDA 학습과 내보내기 이후 전체 후보로 올린다. [FPN](https://arxiv.org/abs/1612.03144) · [YOLO26-P2 구성](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/cfg/models/26/yolo26-p2.yaml)

## 추론 및 선택 조건

1. **같은 D1 가중치에서 값싼 검증을 먼저 한다.** 전체 960/1280, 기존 6타일 640, 겹치는 640 또는 512 타일을 640으로 추론하는 조건, 전체와 기존 타일 결합을 개발 자료에서 비교한다. 타일 크기·격자·머지·커버리지를 남긴다. 필요한 경우 같은 768×640 타일의 입력 960을 추가해 네트워크 입력 확대 효과를 구분한다. 업샘플링의 이득은 원본에서 실제 새 픽셀이 생기는 현상과 구분한다. 모델의 추론 결과를 먼저 본 뒤, 낮은 오탐 기준에서 전체·작은 칼 이득이 있는 입력 한두 가지만 별도 재학습한다. [SAHI](https://arxiv.org/abs/2202.06934)
2. **데이터 비율은 원인별로 바꾼다.** 50/30/20을 기준으로 30/30/40과 70/20/10을 검사할 때 전체 타일 비중 약 48%를 맞추고 양·음성, 그룹, 업데이트를 기록한다. M2가 전역 입력 전용이면 기본 구성에서 P430과 외부 CCTV가 합쳐 80%여서 타일 90%는 현재 데이터 규칙에서 만들 수 없다. 타일 비율을 검증할 때는 출처를 그대로 두고 전체 타일 30%와 48%를 우선 비교한다. 70%는 전역 문맥 유지와 유효 타일 수를 확인한 뒤 한 번 실행한다. 80% P430은 같은 장면의 반복도 증가하므로 기본 비교에서 근거가 나온 경우에만 추가한다.
3. **사람이 확인한 반복 오탐을 학습 쪽에서 보강한다.** 검출 실패와 저점수, 경계 파편, 귀속 오류, 낮은 IoU를 먼저 구분한다. 287장 확인용 오류의 원본은 개발 확인 구간에 둔다. 유사 사례는 별도의 허용 train 구간에서 수집·검수하고 양성 목록과 총 음성 수를 맞춘다. 실제 P430 Hard Negative는 OHEM과 문제의식이 유사한 오프라인 실험이다. Legacy와 합성은 출처·권리·중복 검사 및 별도 가설에 따라 후속 범위에 둔다. [OHEM](https://arxiv.org/abs/1604.03540)
4. **증류는 이긴 teacher와 가용 GPU가 확보된 뒤 한 쌍만 시험한다.** PC13의 Ultralytics 8.4.152 설정 파일에서 `distill_model`, `dis`와 P2 YAML을 확인했다. 사용할 GPU에서 일반 P3–P5 teacher/student의 task·class·feature shape와 짧은 CUDA 실행을 확인한다. Teacher가 같은 개발 조건에서 D1보다 분명히 개선되고 Orin에서 직접 쓰기 어려우면 상위 teacher → YOLO26n의 증류와 일반 n을 같은 초기값·자료·입력·seed·예산으로 비교한다. `dis=6`은 설치본의 시작값이다. 공식 구현은 Detect에 입력되는 특징의 점수 가중 L2이며, 전경·배경 및 전역 관계를 사용하는 FGD 논문과 구분한다. P2의 4개 특징맵과 표준 모델의 3개를 연결하는 증류는 호환성 확인이 필요하다. Teacher와 student의 기본 경로는 같은 입력을 받으므로 증류가 타일 없이 잃는 원본 픽셀을 복구한다고 가정하지 않는다. [Ultralytics 증류](https://docs.ultralytics.com/guides/knowledge-distillation/) · [FGD](https://arxiv.org/abs/2111.11837)
5. **후보 채택과 런타임.** tune에서 원본 좌표 기준으로 임계값을 고정하고, 개발 확인에서는 그대로 적용한다. 작은/그 외/전체 recall, AP50·AP50–95, 전체 FP와 음성 오탐을 각각 보고한다. 90%·80% 목표는 이 표본에서 각각 53/58·112/140에 해당하는 도전 목표다. 후보 수를 제한하고 상위 조합의 민감도를 이전 촬영의 시간 블록 또는 별도 그룹으로 확인한다. 1·2차를 번갈아 학습하는 검증을 다시 할 때는 반대 세션을 본 D1에서 시작하지 않는다.
6. Orin은 기존 파일 입력에서 단일 960 p95 52.4ms, 6타일 156.5ms로 관측됐다. 새 가중치에는 동일 해상도와 입력으로 전체+고정 ROI, 6타일, 가능하면 TensorRT FP16을 대조한다. 사람 검출·캡처·판단·경보가 포함된 실측 FPS, 프레임 누락, 지연, 메모리를 기록한다. Ensemble과 multi-scale 결합은 보완되는 FN이 검증되는 경우 오프라인 상한으로 평가한다. [Orin 기준 측정](p430-site-finetuning-rationale.md#1124-실행과-확인)

11/24 최종 영상은 학습·오류 분석·증류·모델 선택에서 분리한다. 기존 287장 확인셋은 개발용이다. B4는 사람이 확인한 Holding 라벨이 확보되는 대로 별도로 학습한다. 최종 검출기 동결과 11/30 마감 전에 승인된 개발·Orin 평가로 선택한다. 추가 모델이 마감까지 검증되지 않으면 D1을 비교 기준 및 예비 후보로 확보하고, 실제 배포는 시연 런타임 확인 뒤 결정한다. 증류·대형 모델이 마감을 넘기면 별도 후속 연구로 기록한다. 독립 평가는 동결된 공통 검출 로드를 B0~B4에 적용하고 Event Recall, F1, False Alerts/h와 경보 지연을 보고한다.
