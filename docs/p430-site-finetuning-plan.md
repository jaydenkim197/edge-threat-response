# P430 설치 환경 맞춤형 최종 학습 계획

2026-11-24 · `PROPOSAL` · 11월 30일 개발·평가 마감

설치된 P430에서 작은 칼을 검출하고, 사건 재현율을 높이면서 오경보를 억제할 모델을 선정한다. 일반화 주장은 동일 설치 환경에서 별도로 촬영한 최종 영상에 한정한다. 기존 2차 개발 촬영의 칼 박스 짧은 변 중앙값은 960 입력에서 8.3px다. 기존 가중치의 작은 칼 검출은 0/316, 기존 가중치에 타일 추론을 적용하면 5/316, T1 혼합은 10/316이었다. 낮은 점수까지 포함한 기존 타일 후보 199/316은 정답과의 후보 겹침이고 실제 경보 정확도는 별도 검증한다. [통합 학습 결과](../reports/training/p430-integrated-2026-11-22/report.md) · [기존 타일 실험](../reports/evaluation/p430-alternatives-2026-11-21/report.md)

## 자료와 분할

- 사용자 확인으로 최종 영상의 촬영·편집을 마쳤다. 원본 녹화 SHA-256, 편집본·파생본 SHA-256, 촬영 세션과 컷/시간 구간을 연결한 보호 목록을 확정한다. 같은 원본 또는 동시 촬영에서 나온 편집본·프레임이 발견되면 그 원본 그룹을 개발·학습 풀에서 제외한다. 후보를 고르기 전까지 최종 영상·점수는 봉인하고, 보호 검사는 계보 및 해시로 수행한다.
- 기존 P430 1·2차 1,901장, 외부 CCTV 1,135장, M2 11,884장은 제외 전 후보 수다. 기존 외부 검증 271장과 보호 그룹을 유지한다. P430 1·2차는 각 영상에서 촬영 테이크 또는 연속 시간 구간 전체를 묶어 train/tune/dev-check를 나눈다. 목표는 70/15/15다. 인접 분할 사이 10초부터 완충 구간을 확보하고, 같은 테이크·사건·유사 프레임 그룹은 한 분할에 두므로 필요하면 비율과 완충을 조정한다. tune과 dev-check의 작은 칼, 양·음성, 사건 수를 먼저 기록한다. 두 구간의 양·음성 사건 수가 부족하면 기존 세션 교차 검증으로 비교하고 그 한계를 보고한다.
- 관심 영역과 타일의 검수 범위는 확인된 중앙 1920×1080이다. 4K 원본의 검수 밖 배경은 칼이 없다는 근거로 사용하지 않는다. 타일·증강·크롭의 parent ID와 분할을 유지한다. 출처별 고유 부모 수와 반복 추출 수를 구분한다.

## 1차 학습 네 조건

| 장비 | 학습 입력 | Backbone |
| --- | --- | --- |
| PC11 | 전체 프레임 · 대조군 | 전체 학습 |
| PC12 | 전체 프레임 | 동결 |
| PC13 | 타일 + 전체 프레임 | 전체 학습 |
| PC14 | 타일 + 전체 프레임 | 동결 |

- 공통 출발점은 이전 S1+CCTV 혼합 YOLO26n이다. 시작 설정은 640 입력, batch 8, AdamW, LR 0.0001, warm-up 1 epoch, 약증강, 12 epoch × 8,192회 추출이다. 총 12,288개 미니배치를 맞춘다. 주 비교에서는 기존 일반 실사·개발 외부 CCTV·P430의 부모 순서와 양·음성 비율, seed, P430 50% / 외부 CCTV 30% / M2 20%의 추출 비중을 고정한다. M2는 출처·그룹 균형 목록을 순환하며 실제 사용한 고유 수를 기록한다.
- 타일 조건은 P430·외부 CCTV 추출 중 유효한 뷰에서 약 60%를 타일로 바꾸고 나머지는 전체 프레임을 유지한다. 같은 부모를 뽑는 대조군과 비교한다. 기존 평가와 같은 768×640 겹침 타일 6개를 시작값으로 사용한다. 소형 양성에서 원본 박스 면적 80% 이상 보존되는 타일을 우선하고, 불완전한 칼이 남은 타일은 음성 목록에서 제외한다. 타일 좌표·라벨의 원좌표 왕복, 경계, 원본 그룹, 타일별 양·음성 수를 검사한다. 유효 뷰가 없으면 부모 전체 입력으로 되돌리고 치환 수를 기록한다. [SAHI 연구](https://arxiv.org/abs/2202.06934)
- PC13 설치본 8.4.152에는 최신 문서의 `tile=`이 없다. 오프라인 타일/YOLO 라벨을 생성해 고정 버전에서 사용한다. `freeze`는 지원한다. 설치된 YOLO26 설정의 backbone 0–10을 출발점으로 실제 checkpoint 구조를 확인하고, 첫 배치에서 동결 계층과 갱신할 계층을 검증한다. 특징을 고정하는 조건은 backbone BatchNorm의 running statistics도 검사하고 유지한다. [Ultralytics 타일 참고](https://docs.ultralytics.com/guides/high-resolution-tiling/) · [동결 옵션](https://docs.ultralytics.com/modes/train/#train-settings)
- 작은 칼·전체 recall, AP50/AP50–95, 검출된 음성 프레임과 전체 FP를 원본 좌표에서 계산한다. 같은 개발 원본에서 **기존 가중치와 새 가중치에 전체 화면 및 같은 타일 추론을 각각 적용**한다. 학습용 타일은 정답을 쓸 수 있고, 추론용 타일 위치는 프레임과 고정 ROI로만 정한다. 중복 박스는 원좌표 복원 후 합친다.

## 2차 학습과 GPU 사용

1. 1차에서 가장 좋은 표현과 동결 조건을 유지하고, P430/외부 CCTV/M2 추출 비율을 30/30/40과 70/20/10으로 바꾼다. 50/30/20을 중심 조건으로 사용한다. 설치 장소의 사람이 확인한 반복 오탐만 별도 시료로 만든 대조 실험을 1건 실행한다. 지역·테이크별 상한을 두고 양성 수와 총 음성 수는 유지한다.
2. 가장 가능성 있는 후보 두 개는 seed를 바꿔 반복한다. 3080 두 장을 사용할 수 있으면 YOLO26s를 동일 데이터·비슷한 업데이트 예산으로 한 번 비교한다. 별도 크기의 신뢰 가능한 초기 가중치를 기록하고, 초기 학습 이력이 다르면 모델 크기만의 영향으로 해석하지 않는다. 같은 비용에서 세부 묘사가 늘어나는지 확인하려면 추가 타일 크기는 512급 한 조건으로 제한한다. 1차 효과와 11/26 동결 기한을 보고 후속 실행 범위를 정한다.
3. 11/24 확인 시 PC13 RTX 3060과 Orin SSH에 접속했다. PC11·12·14 SSH는 타임아웃됐으며 3080 서버는 사전 확인이 필요하다. PC13에서 데이터 준비와 주력 타일 학습을 먼저 진행할 수 있고 나머지 실험은 GPU가 확인되는 순서대로 배정한다.

## 후보 선택과 마감

- **검출 진단:** 이전처럼 음성 프레임 100장당 오탐 1장 이하의 검출점을 기록하고, 후보를 낮은 점수부터 보존해 confidence별 recall/FP 및 크기 구간을 분석한다. 1차·2차의 점수는 각 조건의 재표현 비교용이며 독립 최종 성능이 아니다.
- **경보 선정:** 기존 1·2차 개발 영상의 실제 시간축과 사건 시작·종료 정답으로 confidence와 시간 조건을 tune에 맞춘다. 낮은 confidence부터 만든 동일 검출 로그를 B0~B4에서 재사용한다. 최종 비교의 공통 K/N·FSM은 동결한다. dev-check에서 기존 모델과 같은 오경보/시간 상한으로 Event Recall 우선, Event F1 및 경보 지연을 함께 비교한다. 개선이 비슷하면 오경보와 시간 구간별 결과를 함께 보고, 오경보 0건일 때도 관측 시간을 공개한다.
- **Orin:** 상위 1–2개 checkpoint에서 전체 화면, 전체+고정 ROI 2–3곳, 6타일을 동일 개발 영상 조건으로 비교한다. 유효 FPS·프레임 누락·처리 p95·메모리와 경보 시점 측정을 분리 기록한다. 같은 경보 성능이면 더 빠르고 안정적인 설정을 채택한다. 기존 기준, 통합 640 PC13, T1 혼합 PC12를 비교 후보로 보존하고 개발 검증에서 이긴 모델이 없으면 여기서 가장 안정적인 모델을 사용한다.
- **HOI/B4:** 이전 개발 영상에서 사람이 검수한 Holding/Not Holding pair가 확보되면 G/VG를 별도 GPU에서 병행한다. 정답이 불명확한 pair는 보류한다. 승인된 실제 관계 라벨 파일이 없으므로 이 단계는 대기다. [Holding 라벨 규격](hoi-annotation-contract.md)
- **11/24–25** 보호 목록·학습 후보 분할·타일 검증 및 1차 실행. **11/25–26** 후속 학습과 개발 replay, Orin 측정. **11/26** 후보 확정·가중치/런타임·입력·confidence·K/N·FSM·평가 규칙 해시 동결을 목표로 한다. **11/27** 보호된 영상에 설정을 한 번 적용한다. 편집으로 연결된 서로 다른 컷은 원본 시간축에 매핑하고 상태를 초기화해 한 사건으로 이어지지 않게 한다. **11/28–30** 결과 보고.
