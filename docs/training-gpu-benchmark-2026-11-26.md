# GPU 10장 합성 학습 벤치마크

2026-11-26 KST · 연구실 Linux GPU 여섯 장은 한 번에 한 장씩 실행했다. Windows 네 대는 각각 독립 실행했다. 공통 조합은 PyTorch 2.6.0+cu124, torchvision 0.21.0+cu124, Ultralytics 8.4.152다. 열 장에서 CUDA NMS와 YOLO26n 단일 클래스 학습 스텝이 성공했다. Linux wheel의 `sm_60`으로 두 GTX 1080 Ti(CC 6.1)에서 검증했다.

측정은 640px 합성 텐서·FP32(TF32 끔)·고정 seed·AdamW를 사용했다. 배치마다 warm-up 2회 뒤 6회 중 중앙값으로 처리량을 계산했다. 여유 기준은 PyTorch가 보고하는 장치 가용 용량의 10%와 1 GiB 중 큰 값이다. **최대 통과 배치는 시험한 배치 목록 안에서 확인한 값**이다. 데이터로더, augmentation, validation·저장, 지속 부하를 포함한 운영 안정 배치는 별도로 확인한다.

## 서버 단일 작업 계측

- 18:24 조회의 가용 RAM은 248 GiB, 홈 NVMe 여유는 279 GiB였다. 내 가상환경의 라이브러리에서 128 MiB 직접 순차 읽기 1회는 도구 표시 2.7 GB/s였다. JPEG 다건 읽기·변환 및 동시 체크포인트 I/O는 별도로 확인한다.
- 합성 sweep 동안 측정한 서버 `vmstat` 표본의 최대 순간 iowait와 swap in/out은 0이었다. GPU 온도/전력의 1초 표본 최대값은 #0 40°C/265 W, #5 41°C/279 W, #1 65°C/296 W, #2 54°C/326 W, #3 73°C/261 W, #4 30°C/249 W였다. 카드 별 냉각 상태와 부하 시간에 따라 달라질 수 있고, PSU·회로의 실제 용량과 벽전력을 확인해야 동시 실행 상한을 정할 수 있다.

## 재현 위치

Linux 원시 step·환경 freeze·1초 telemetry는 사용자 홈의 `etr-gpu-benchmark-20261126`에, Windows 네 대 요약 전 원시 로그는 각 사용자 홈의 `etr-benchmark-yolo-20261126.log`에 둔다. 측정에 사용한 스크립트 SHA-256은 `711dcac7f4c91f4e320091e9a0c328dee58966e331926b252310def6c5c7cc7e`다. 실행 전 호스트에서 GPU UUID와 점유를 확인하고 전용 `YOLO_CONFIG_DIR/Ultralytics` 디렉터리를 만든다. 그다음 한 UUID만 `CUDA_VISIBLE_DEVICES`에 설정한다. Linux 공통 옵션은 `--steps 6 --batches 8 24 32 36 40 48 56 64 72 80 96`, Windows는 48까지, s/m 추가 측정은 `--steps 6 --batches 4 8 12 16 24 32 40`이다.
