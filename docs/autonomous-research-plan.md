## 1. 목적 및 우선순위

Jetson Orin Nano 기반 흉기 위협 감지 시스템에서 기존 D1보다 우수하고 실제 배포 가능한 객체탐지 모델 또는 탐지 파이프라인을 확보한다. 기존 Track A·B·C 연구와 자동 실행 환경을 활용하며, 이미 수행한 작업을 반복하지 않는다. 연구 목표를 설정하고 나머지 방법은 측정 결과에 따라 선택한다.

Track A = YOLO 탐지 최적화, Track B = 대안 탐지 방법, Track C = Holding/HOI 및 사건 수준 검증. 같은 실행 슬롯에서 READY인 A를 우선하고, 없으면 B를 배정한다. C는 작업별 선행 입력을 갖춘 후 잔여 자원에서 진행한다. 필요한 제출·평가 시간을 먼저 확보한 뒤, 독립적인 B 작업은 같은 슬롯에 준비된 A가 없을 때 배정한다. 이미 시작한 작업은 정당한 오류·안전 사유 없이 중단하지 않는다.

프로젝트 마감은 2026-11-30이다. 필수 모델·설정 동결, 실기기 검증과 평가·제출에 필요한 시간을 먼저 확보한다. 목표에 미달한 연구는 남은 가설과 재개 지점을 기록한다. [Master Plan](project-plan.md)

## 4. 목표 및 공통 검증 계약

최종 목표는 동일한 모델/파이프라인의 고정 운영점에서 아래를 동시에 충족하는 것이다.

| 지표 | D1 기준 | 도전 목표 |
|---|---:|---:|
| Small Recall | 47/58 (81.0%) | ≥53/58 (≥90%) |
| Overall Recall | 81/140 (57.9%) | ≥112/140 (≥80%) |
| Negative Frame FP | 0/147 | ≤1/147 |
| AP50 | 61.82% | >61.82% |
| AP50–95 | 18.04% | >18.04% |
| 배포 | 기존 Orin 파일 입력 기준 | 실제 운영 경로의 사전 정의 기준 충족 |

기존 원좌표·일대일 IoU 0.50 매칭, small 정의, 분모와 AP 평가 규약을 유지한다. 각 후보의 임계값·후처리·결합 규칙·시간적 설정은 tune에서 결정하고 dev-check에는 고정한 채 적용한다. AP는 공통 평가 규약에 따라 운영 임계값 적용 전 점수 순위로 계산한다. AP의 목표 판정에는 반올림 전 점수를 사용하고, D1 원시 점수와의 차이도 기록한다. TP/FP/FN, 전체 FP 박스, precision, small/그 외 Recall, AP50/AP50–95 및 세션별 결과를 함께 기록한다. 여러 후보의 서로 다른 지표를 합쳐 목표를 충족한 것처럼 보고하지 않는다. Tune의 운영점 선택 및 dev-check 반복 평가 이력을 보존한다.

기존 287장 dev-check는 이미 여러 차례 참조한 개발 자료다. 새로운 가설·하이퍼파라미터·임계값 선택은 가능한 한 train/tune에서 수행하고, dev-check 조회 횟수와 후보를 제한한다. 개발 확인셋의 구체적 실패 프레임·크롭을 train에 넣거나 의사 라벨로 쓰지 않는다. 개선 근거가 필요하면 승인된 train 구간에서 유사 사례를 찾는다. 재현은 추가 seed 및 승인된 원본 그룹/세션 교차 검증으로 확인한다. 엄격 세션 홀드아웃은 평가 원본에 미노출된 초기값부터 matched 학습을 수행한다. 그룹 수가 부족하면 불확실성을 명시한다.

11/24 독립 최종 영상·파생 프레임·정답은 모델 학습, 증강, SSL, 배경 기억, 후보/라벨 생성, 증류, 오류 분석, 임계값 및 모델 선택에서 제외한다. 원본·파생물·근접 중복은 동일 계보로 보호한다. 동결 후 사전 등록된 독립 평가만 별도로 실시하며 그 결과를 이용해 이번 모델을 재선택하지 않는다. 개발 지표로 독립 일반화 성능이나 사건 경보 성능을 주장하지 않는다.

## 5. 후속 연구 의사결정 순서

아래는 현재 증거 기반의 우선순위이며 고정 실행 목록이 아니다. 원래 Track A/B 문서의 모든 가설과 상태를 보존하고, 선행 결과로 새로운 근거가 생긴 경우에만 재검토한다. 각 실험은 목적·대조군·변경 변수·입력·예산·승격/중단 조건을 실행 전에 남긴다.

### P0 — 실행 복구와 값싼 진단

1. 앙상블 수집기 파일명 처리 오류를 최소 재현하고 수정한다. 기존 예측의 경로/해시, 동일 image ID·좌표·split·GT·모델별 score 규약을 대조하고 회귀 테스트를 수행한다. 올바른 완료 영수증과 평가 입력을 확인한 후 재사용한다. 데이터와 모델이 이미 존재하는 경우 재학습하지 않는다.
2. D1, MIX70, seed 3409 등 저장된 공통 tune/dev 예측을 이용해 후보 보완성, 공통 FN·FP, 위치/점수/병합/경계 실패를 분리한다. 가능한 경우 train/tune에서 후보 상한과 사전 정의한 결합 방법을 비교한다. 개발 확인셋에서 과도한 조합 탐색을 피한다.
3. 학습 모델을 우선 다시 비교하기보다 통과 조건에 맞는 저비용 추론·후처리 실험을 먼저 수행한다. D1 기준선을 보호하고 결합 비용과 오탐 변화를 함께 측정한다.

### P1 — 현재 가장 유망한 개선 가설

- ALT-01 후보 재검증: 기존 Track B 계획의 승인된 train 크롭 검수와 데이터 계약을 충족한 뒤 동일 후보 단독 기준과 재검증 비교를 수행한다. 후보 oracle은 상한으로만 기록하며 실제 후보의 누락/오탐/지연을 확인한다. 검수 대기 시 다른 READY 실험으로 넘어간다.
- MIX70: 높은 TP와 늘어난 음성 오탐의 원인을 train/tune 자료에서 확인한다. 반복 혼동 음성의 검수된 동수 교체/보강을 우선 검토하고, 기준 MIX70 또는 D0 초기 matched 학습과 비교한다. 출처 비율과 타일 비율 등은 한 번에 하나씩 변경한다. MIX80은 원래 승격 조건 미충족 여부와 새로운 근거를 확인하고, 실행 필요성이 입증되면 별도 조건으로 사전 등록한다. 단일 seed 이득은 재현 전 확정하지 않는다.
- D1 + Lanczos: 같은 실제 승인 개발 영상/동일 카메라 입력·비용에서 native와 비교한다. 축소·복원 성능만으로 실기기 개선을 주장하지 않는다. TensorRT 또는 다른 추론 최적화와 결합할 때 수치 동등성과 좌표를 검사한다.

### P2 — 배포 검증 및 후속 가설

- 원래 계획의 타일 비율, 추가 seed, 교차 세션, 입력 열화, 대안 아키텍처 및 시간 정보 가설은 근거·승인 입력·연산 비용에 따라 실행한다. 고정 카메라의 배경 방법은 기존 RGB 경로를 보존하고 정지 대상 손실을 평가한다. 시간적 방법은 미래 프레임을 참조하지 않고 원본 PTS/경계를 보존한다.
- 모델 구조 비교는 도메인 초기화 차이를 분리한다. P2는 개발 오탐 상한을 넘었고, 고해상도 학습과 l/x는 큐의 선행 조건 미충족으로 건너뛰었다. 새 비교 근거가 생기면 재검토한다. 증류에는 우세하고 호환되는 teacher, 조건을 맞춘 대조군, 배포 비용의 근거가 필요하다.
- 승인된 개발 영상으로 Orin의 파일 및 실제 RTSP/카메라 경로를 구분해 검증한다. 기존 야간 문서의 파일 입력 p95(전체 52.7ms, 6타일 153.3ms, 전체+ROI 106.7ms)는 탐지기 기준 기록이다. 사람 검출·판단·경보·캡처를 포함한 전체 파이프라인 실측을 별도로 남긴다. 장비·전원·런타임·목표 sample rate를 확인하고, 후보 결과를 보기 전에 [Track B의 J 배포 기준](p430-track-b-alternative-detection-plan.md#4-공통-검증-방법과-통과-기준)을 참고해 적용 기준을 확정하고 변경 근거를 기록한다. 목표 FPS·유효 FPS·drop·p95·RAM·온도·queue 안정성을 측정한다. TensorRT 변환은 동일 입력에서 출력 동등성과 실제 속도를 확인한 후 채택한다. 보드 OS/드라이버를 임의 업그레이드하지 않는다.
- Track C의 G/VG 학습과 B4 평가는 승인된 실제 Holding 정답이 필요하다. B0~B3 사건 평가는 동결한 검출기와 사건 정답을 준비해 진행할 수 있다. 비교 중에는 동일 검출기·입력과 해당 모드의 공통 K/N·FSM·사건 매칭 규칙을 유지한다. B4는 관계 점수의 기여를 별도로 평가한다.

기존 계획에 없더라도 기술적으로 타당한 추가 방법은 학술 자료·공식 문서·재사용 가능한 구현을 근거로 제안 및 실행할 수 있다. 단, 데이터 승인, 보안, 비용, 하드웨어·평가 경계 및 마감 조건은 변경할 수 없다. 우선순위와 승격 조건을 바꿀 때 원래 규칙 및 변경 근거를 남기며, 최종 성공 기준은 편의상 완화하지 않는다.

## 6. Queue·GPU 운영

사용 승인된 자원은 PC11~14의 RTX 3060 12GB ×4 및 `lab-gpu`의 RTX 3090 24GB ×2, RTX 3080 10GB ×2, GTX 1080 Ti 11GB ×2다. RTX PRO 6000은 제외한다. 사용 승인과 현재 점유·동시 부하 안전은 구분한다. 기존 벤치마크와 실제 처리량을 활용하고 정밀 벤치마크를 재수행하지 않는다.

연구실 서버의 검증된 동시 실행 상한은 현재 1이다. PSU/전원 회로/냉각 여유를 확인할 수 없는 동안 상한을 유지한다. 확인된 안전 범위에서만 기존 자원 배정 계획에 따라 단계적으로 확장한다. GPU UUID·점유·잠금과 가용 디스크를 실행 전에 확인한다. 다른 사용자의 프로세스나 파일은 변경하지 않는다. sudo, 전역 드라이버 변경, 임의 전력 조정은 금지한다. 대형 모델/해상도/증류는 적합한 3090에 우선 배정하고, 1080 Ti는 실제 호환성과 전체 완료 시간 개선이 확인되는 작업에 활용한다.

기존 Queue 상태 및 Worker 구현을 먼저 사용한다. 새 실험에는 ID, 선행 조건, 실행/건너뜀 조건, 입력 승인, 실행 장비, GPU 요구, 비교 기준, 명령, 출력 위치를 기록한다. 큐의 READY/PENDING/RUNNING/SKIPPED/FAILED/COMPLETED는 Worker 상태와 영수증으로 확인한다. 승인 또는 입력을 기다리는 큐 항목은 PENDING으로 기록된다. 기존 지정 호스트 기반 배정은 동적 이동을 보장하지 않는다. 필요한 경우에만 안전한 범위의 변경을 구현하고 테스트한다. 중복 Worker/학습을 실행하지 않고 원격 연결 실패 시 기존 PID, 잠금, 영수증 및 체크포인트를 먼저 확인한다. optimizer 상태가 없는 가중치 재학습을 정확한 resume이라 부르지 않는다.

호스트 간 결과 동기화와 분기에는 Windows 중계 PC의 전원과 해당 호스트까지의 네트워크/VPN이 필요하다. 원격 독립 실행과 각 Worker가 로컬에서 판단할 수 있는 후속 작업은 SSH/Codex 종료 후에도 유지된다. 데이터 사용은 기존 승인과 `RAW-*` 예비 학습 범위를 따른다. 추가 비용·유료 서비스·미승인 장비·전역 설정 변경은 사용자 승인 전 보류한다.

## 7. 토큰 절약과 연구 지속성

Codex는 연구적 판단(결과 분석, 가설 선택, 문헌 조사, 설계/코드, 중요 예외 처리)에 집중한다. Python Worker와 중계 프로세스는 학습·상태 감시·체크포인트·평가·결과 수집·정해진 분기·후속 실행을 담당한다. 이미 등록한 작업을 기다리기 위해 반복 SSH/로그 조회, 장시간 sleep 기반 모델 루프, 무의미한 추가 작업을 하지 않는다. 구조화된 요약과 변경된 상태만 필요할 때 확인한다. 실험은 적절한 묶음으로 설계하고 독립 실행에 맡긴다.

학습 결과나 외부 승인만 기다리는 경우 현재 작업의 독립 실행 여부를 확인하고 가능한 후속 실험을 등록한다. 재개 조건(필요한 완료 영수증/결과/승인), 최고 후보, 대기 작업, 다음 판단을 기존 개발 로그·보고서 및 Queue 상태에 기록한다. 반복 모델 호출을 줄이고 일시정지가 필요하면 사용자에게 요청한다. Goal 일시정지는 사용자가 명시적으로 요청한 경우 적용한다. Worker의 작업 대기와 Goal 상태는 별개로 관리한다.

기존 문서 거버넌스를 따른다. 별도의 중복 상태 트리나 매번 동일한 상태 문서를 만들지 않는다. 실험별 ID·가설·대조/통제 변수·입력 계보·코드/환경·seed·설정·데이터/가중치 해시·장비·원시 결과 위치·지표·실패·한계를 보존한다. material change는 기존 `docs/development-log.md`와 관련 보고서/검증 문서에 기록하고 검증 후 의도한 파일만 commit/push한다. 인증 정보·개인키·민감 영상·보호 데이터·대용량 원본은 Git에 넣지 않는다.

## 8. 완료, 대기 및 중단

- 성공: 4절의 목표를 한 후보에서 동시에 충족하고 개선 재현성, Orin 운영 가능성, 최종 가중치/설정/실행 방법 및 평가 증거를 확보한다. 후보와 운영 조건을 동결한다. 독립 평가와 논문/시연 준비는 승인된 절차로 별도 진행한다.
- 대기: 실행 가능한 연구가 없고 Worker 완료 또는 사용자 승인만 남은 상태. 7절에 따라 재개 조건을 기록하고 일시정지가 필요하면 사용자와 조율한다.
- 미달/중단: 마감, 데이터, 연산, 사용량, 안전 제약 또는 타당한 가설 소진으로 추가 연구가 불가능한 상태. 최고 후보와 D1 대비 실측, 목표별 차이, 실패한 방법, 남은 작업/승인, 재개 지점을 보고한다. 마감에 대비해 D1 예비 후보와 기존 독립 평가 계획을 보존한다.

정해진 실험 개수나 코드/문서 작성 완료만으로 성공 처리하지 않는다. 반대로 낮은 기대 효과의 실험을 무한히 추가하지 않는다. 연구 성과와 실제 배포 가능성에 집중한다.
