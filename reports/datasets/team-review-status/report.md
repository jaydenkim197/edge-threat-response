## 검사와 갱신

- 기존 `tools/team_review_status.py` / `inspect()`의 SQLite 읽기 전용 조회, `PRAGMA quick_check`, 테이블별 행 수·SHA-256을 재사용했다. 43개 데이터/팩, 53개 DB를 확인했다.
- 영상 판정은 domain·칼 유무·박스 개수만 추가 집계했다. 이름·식별자·메모·원본 payload·DB/config 원본·접속 비밀은 JSON에 포함하지 않는다.
- 서비스 실행 중 DB별 읽기 트랜잭션으로 조회한다. 전체 DB의 같은 시점을 고정하는 원자적 백업이나 배포 전 정지 백업을 대신하지 않는다.
- 후속 조회는 PC13에서 `tools/team_review_status.py --config data/review/team-server/config.json --output data/review/team-server/<local-status>.json`을 사용한다. config는 출력하거나 Git에 복사하지 않는다.
- 1시간 간격 자동화는 판정/수정 이력 변화가 있을 때 갱신한다. 시각·세션/배정 만료만 바뀌면 커밋을 만들지 않는다. 같은 판정 수라도 수정 이력이 달라지면 기록한다.
- 사이트 변경은 검증 후 코드·문서와 함께 push한다. 모델 학습과 평가 분할 변경은 기록 동기화 범위에 없다.
