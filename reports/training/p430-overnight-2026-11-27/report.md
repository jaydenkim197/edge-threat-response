# P430 야간 학습 결과

2026-11-27 KST · 2차 최적화 개발 평가 `VERIFIED` · [실험 설계](../../../docs/p430-phase2-optimization-plan.md) · [야간 큐](../../../docs/p430-overnight-queue.md)

**이번 학습에서는 D1을 교체할 후보를 확보하지 못했다.** D1은 음성 프레임 오탐 0/147에서 작은 칼 47/58, 전체 칼 81/140을 검출했다. MIX70은 전체 칼을 97/140까지 검출했지만 오탐 7/147로 상한 1/147을 넘었다. 같은 D1에 Lanczos를 적용한 개발 실험은 50/58, 92/140, 1/147이었다. 원본을 2배 축소한 뒤 복원하는 조건에서 얻은 결과이므로 실제 입력에서도 이득이 유지되는지 확인해야 한다.

## 평가 조건

- 11/17·11/19 촬영의 시간 구간을 나눈 개발 자료를 사용했다. 298장 튜닝셋에서 조건별 체크포인트와 임계값을 고른 뒤 287장 개발 확인셋에 적용했다. 확인셋에는 칼 정답 140개(소형 58개)와 음성 프레임 147장이 있다. 11/24 독립 평가 영상과 파생 자료는 이번 학습·튜닝·모델 선택에서 제외했다. [분할과 학습 기준](../../../docs/p430-site-finetuning-rationale.md)
- 기본 추론은 중앙 1920×1080에서 768×640 겹침 타일 6개를 추출해 모델 입력 640으로 처리하고 원본 좌표에서 합치는 방식이다. 운영점의 검출은 IoU ≥ 0.5로 짝지었다. 음성 오탐은 검출이 하나 이상 나온 음성 프레임 수이며, FP 박스는 정답과 짝지어지지 않은 전체 박스 수다. AP는 여러 점수에서의 검출 성능을 집계한다.
- 비교에 쓰는 음성 오탐 상한은 1/147(0.68%)이다. 전체 Recall 80%와 작은 칼 Recall 90%는 이번 개발셋의 도전 목표이며 필요한 검출 수는 각각 112개, 53개다. 어떤 조건도 세 가지를 함께 충족하지 못했다.

- **출처 혼합.** P430/외부 CCTV/M2를 30/30/40 → 50/30/20(D1) → 70/20/10으로 비교했을 때 전체 검출은 34 → 81 → 97이고 AP50은 37.14% → 61.82% → 71.72%였다. epoch당 8,192회 추출과 타일 3,932회를 고정했다. 세 출처의 비율이 함께 바뀌고 각 변형은 한 번씩 실행됐다. MIX70의 높은 검출 수는 설치 환경 데이터가 유용하다는 가설을 뒷받침하며, P430 비율만의 효과와 최적값은 추가 비교가 필요하다. 80% 조건은 MIX70이 오탐 기준을 넘겨 이번 큐에서 건너뛰었다.
- **타일 학습.** 타일 30%는 D1의 약 48% 대비 작은 칼·전체 검출이 모두 떨어졌다. 70%는 전체 검출이 89/140으로 늘었지만 작은 칼이 45/58로 줄고 음성 오탐이 3/147로 늘었다. 현 조건에서는 약 48%를 기준으로 유지한다.
- **체크포인트와 학습률.** 두 재현 seed 모두 첫 epoch의 EMA가 튜닝에서 선택됐다. 확인셋 전체 검출은 77~91개, 음성 오탐은 3~4장이었다. 초기 체크포인트를 평가할 근거는 확보했고 seed가 달라도 같은 운영점을 얻는지는 남았다. LR을 0.0001에서 0.00005로 낮춘 조건은 오탐 0장을 유지했으나 전체 검출이 81개에서 69개로 감소했다.
- **모델 크기와 P2.** COCO 초기 n/s/m은 같은 데이터·예산으로 비교했고, D1은 S1+CCTV 학습 이력이 있는 D0에서 시작했다. s/m의 AP는 D1보다 높아도 해당 운영점의 검출과 오탐 기준에서는 D1이 유리했다. 이 비교로 모델 크기나 P2 구조 자체의 효과를 확정할 수 없다. 연구실 P2는 12 epoch 후 11/26 23:20 KST에 평가까지 완료했다. 전체 화면 960에서 택한 `epoch6.pt`는 15/58, 36/140, 1/147, AP50 16.25%였다.

512/640 타일에 중첩 25/40%를 적용한 네 조건은 모두 오탐 상한을 넘었다. 가장 많은 칼을 검출한 640/40%도 작은 칼 48/58, 전체 84/140에 음성 오탐 3/147이었다.

D1의 누락 59개 중 45개(76.3%)는 임계값 적용 전 남아 있던 후보와 IoU ≥ 0.5였다. 타일 처리 단계도 추적한 A-TRACE는 이 45개를 점수/매칭으로 분류했고 추가로 병합 제거 7개, 경계 제거 2개, 위치 불일치 4개, 남은 겹침 부족 1개를 기록했다. 후보가 겹친 45개는 재검증할 여지가 있는 수량이며, 오탐을 억제하면서 회복 가능한 검출 수는 후속 평가로 확인한다. D1에서 놓친 59개 중 48개는 소형 구간 밖이었다. MIX70의 전체 검출 이득 16개 중 15개도 이 구간에서 나왔다. [후보 중첩 진단](../p430-phase2-2026-11-26/report.md) · [추적 구현](../../../tools/p430_followup_actions.py)

D1을 Orin에서 개발 파일 24프레임으로 측정한 검출 p95는 전체 960 52.7ms, 6타일 153.3ms, 전체 960+고정 ROI 106.7ms였다. 이 측정 범위는 파일 입력의 검출 경로다. 실제 P430 스트림의 사람 검출·관계 판단·경보 지연과 Lanczos의 Jetson 성능은 남아 있다.
